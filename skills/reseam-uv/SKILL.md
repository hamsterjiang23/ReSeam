# ReSeam UV 复用

在 ReSeam 仓库运行 `uv run reseam tools list`，随后对需要的操作运行
`uv run reseam tools describe <工具名>`。参数以当前 CLI 说明为准。此 Skill 的 LLM 就是调用工具的 Agent，无需另接模型 API。

每次调用写一份 JSON 请求，再运行：

```text
uv run reseam tools run <工具名> --request <request.json> --output <从未存在的新目录>
```

文件引用使用绝对路径。标准输出是结果 JSON；读取输出目录的 `result.json`、`process.log` 及返回的证据文件。默认每项操作 300 秒，可在请求中设置 `timeout_seconds`。不另写几何或烘焙辅助脚本绕过工具门禁。

## 执行路线

1. `asset.import` 冻结原始输入。GLB 是完整材质路径；OBJ 用独立 `reference` GLB 供应真实材质。输入无 UV 时显式设置 `initialize_uv: "xatlas"`。不替换用户输入或历史试验资产。
2. `uv.inspect` 查看编号岛、畸变和重叠；`view.render` 查看真实颜色、棋盘格、编号岛、接缝或错误面。需要定位时传入 `pick_pixels` 取得原面 ID 与重心坐标，再用 `selected_faces` 或 `region_id` 查看局部。诊断视图不替代质量渲染。
3. 先用 `uv.pack`、`material.bake`、`quality.validate` 建立无共享基线。记录全部配置、分辨率、阈值和耗时。基线不通过时报告失败区域，先排查投射、拓扑、UV 或材料支持问题。
4. `reuse.find_candidates` 给出候选；结合模型图和材质，用 `region.define` 保存语义区域、保护面及证据。区域可跨旧岛，不按坐标接近焊接。保存包含原面 ID、理由、例外面和父状态哈希的提案；`reuse.check_pair` 检查对应及最终 UV，拒绝不等于数学上无法复用。
5. 对通过的提案用 `reuse.apply` 建新快照，必要时 `uv.pack`。同组保持共同映射；差异区通过整面独占处理。`exclusive` / `unshare` 用于回退局部关系。不要强制镜像模型几何。
6. 对新快照重新 `material.bake`、`quality.validate`；旧贴图或旧验收不能用于改过 UV 的状态。比较完整实际通道和 mip，不以岛少、填充率或 BaseColor 预览代替质量验收。
7. `asset.export` 导出已验收结果。没有通过结果时可用明确的 `mode: "diagnostic"` 导出失败证据，并保留最好已通过快照。最终报告链接真实贴图、原始/修改 UV、渲染、最低已验收字节数及所有拒绝/超时成本。工具完成、节省存储、艺术验收分别报告。

## 整龙迭代与颜色范围

本轮 tripo_p2 的执行合同在仓库 `docs/dragon-llm-reuse-plan.md`，完整参数以 `tools describe` 为准；接口列出不代表后端冒烟或整龙验收已通过。

- 按脚与腿、翼膜与翼骨、重复角刺推进。头脸和明显特征默认保护。先取得部件级共享，再扩展整龙；同一假设连续三次失败后，依据错误面更换对应、区域或展开方法。
- `uv.reparameterize` 显式选择区域及几何后端。本轮允许 OptCuts 作为实验展开后端；先核验面角映射、原几何不变和运行版本。它不替代跨部件对应，也不改变历史自研求解器的范围。
- 仅在用户允许对称化修饰时，选择主纹理成员并用 `material.target` 冻结源贴图及固定对应构成的目标；保护区保持原信号。目标不能由待验收贴图反向生成，外观修改量与重建误差分别报告。
- `material.bake mode=basecolor_reuse` 使用明确的颜色目标，再调用独立验收与导出。其通过只代表报告声明的 UV＋BaseColor 范围，不能变成完整 PBR、GPU 或艺术通过。`basecolor_diagnostic` 仍保持仅诊断身份。
- 冻结对称化目标后，为它单独运行无共享对照。新龙协议验证 LOD 0、1、2；完整 mip 写出不代表其余层通过。纹理尺寸枚举不假定成功单调。

## Baseline 与步骤证据

整龙实验必须比较无共享必要修复、OptCuts 无共享修复、纯几何复用、Agent 迭代复用。受控比较使用相同父资产、预处理、候选池、UV 起点、目标外观、后端、质量与执行预算；不同提案来源的端到端比较单列。失败、超时、未运行都保留，不只输出最好结果。

每次区域定义、对应修正、接缝重构、展开、共享、对称化、排布及缩图，保存父子快照哈希、同视角图、相同口径的指标与差值、理由、工具输入、耗时、失败面和接受结论。消融从同一个父状态出发，只改变研究变量。代码修正若影响 Baseline 或验收，新建冻结轮次并重跑受影响路径，不与旧代码结果混排。

分别报告 UV 连通岛数、独立图块数、共享组及面积、纹素密度、颜色误差、完整 mip 字节和包体。堆叠后的两个连通岛不能误记成一个岛；单对部件或零散三角形成功不能代表整龙完成。

## 失败反馈

- `REJECTED`：读原因和失败面；缩小共享区域、改对应或释放整面例外，再从父快照重新检查。不要调宽阈值后宣称原协议通过。
- `DEPENDENCY_MISSING`：仅安装或配置所需后端；不能悄悄换算法冒充成功。分析不依赖 Blender。
- `TIMEOUT` / `ERROR`：保留日志与已完成证据；重新调用使用新目录。父状态保持不变，失败子产物不参与最优结果比较。
- 参数或父哈希过期：从当前快照重新生成检查提案。
- xatlas 对极小面输出退化 UV：可显式重新导入并设置 `repair_degenerate_faces: true`，将这些原始面隔离为内禀等距三角岛，再 `uv.pack`；检查返回的修复面清单，几何与面数不变。
- 默认支持静态、不透明标准 PBR；额外 Shader、动画、混合/多材质等支持由工具明确判定。不得用伪造贴图补齐不支持的功能。
- 遇到材质扩展不支持但仍需研究颜色/UV，可明确请求 `material.bake` 的 `mode: "basecolor_diagnostic"`；返回颜色贴图与专用预览，永不标为完整材质验收通过，不能输入 accepted 导出流程。

在相同质量条件下比较无共享、纯几何选择与 Agent 选择。预算是有限枚举，不假设求解成功对尺寸单调。只把实际通过的候选称为可用结果；外观仍由用户或艺术家验收。
